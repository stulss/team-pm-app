## 위험 요소

| 위험 | 대응 |
|---|---|
| Vercel 함수에서 Socket.io가 기대대로 동작하지 않음(인스턴스 분산, 연결 끊김) | M0 스파이크로 먼저 검증. 실패 시 Express만 별도 상시 서버로 분리(`DEPLOYMENT.md` §3) |
| 소켓 연결이 함수 최대 실행시간에 끊김 | 재연결(백오프)과 재조회를 기본 흐름으로 구현 |
| Cron 요금제 제한으로 매시간 실행 불가 | M0에서 확인. 불가하면 실행 빈도를 낮추거나 요금제 변경 |
| Transaction pooler에서 prepared statement 오류, 연결 수 부족 | `pg` prepared statement 비활성, 풀 크기 작게, 마이그레이션은 별도 연결 |
| Supabase 무료 플랜 제한(일시정지, 연결 수) | 요금제·연결 수를 M0에서 확인, Session pooler 사용 |
| 일정 지연 | M6~M8은 독립적이므로 범위를 줄일 때 M7(알림)부터 다음 버전으로 이동 |
